# 实验约定

Demo 围绕一个稳定的研究问题持续演化，例如“情绪如何影响记忆的检索与写入”，或“事件间隔如何影响时间判断与回忆”。实验围绕**情绪化记忆库与时间感知**展开，不以完成通用 Agent 功能为目标。

- **问题不变**：直接修改原 Demo。算法、参数、模型、实现和重构由 Git 记录。
- **问题改变**：新建 Demo，使用稳定编号和简短主题名。编号不因内部实现调整而改变。
- **避免过早抽象**：不同 Demo 可以暂时重复实现。只有共用需求经过实验验证并足够稳定时，才考虑移入基础设施。

## 验证方式

先做体感测试，再根据观察到的问题设计对照实验。体感观察、机制推测和实验结果必须明确区分。

关于时间的实验，应明确**现实时间、模拟时间、轮次和调度间隔**分别指什么。固定间隔触发或按轮次衰减不能直接作为“具有时间感知”的证据；有关记忆与情绪的结果也不能自动外推到时间感知。

## 实验记录

以 [Demo 1](../demos/demo1-emotion-memory/README.md) 为例：

~~~text
demos/demo1-emotion-memory/
├── README.md       # 当前研究问题、机制、运行方式、观察和局限
├── emc/            # 实现
├── tests/          # 测试
├── experiments/    # 具有长期比较价值的实验记录
└── results/        # 原始数据与结构化指标
~~~

实验记录需注明关键条件、配置、代码版本并指向相应数据；普通调参、Bug 修复和重构无需另写过程文档。尚未验证的机制应明确标记，不得写成实验结论。

实验可依赖基础设施提供的能力，也可以提出、验证或否定基础设施的接口需求。基础设施尚未提供稳定能力时，允许 Demo 保留独立实现；**不得把某个 Demo 的特定记忆、时间或认知机制直接视为所有实验必须遵循的 Runtime 定义**。
