# 文档与历史约定

## 文件职责

- `README.md`：项目定位、组成与入口。
- `docs/`：研究模型、当前认识与参考资料。
- `rules/`：项目参与者（包括 Agent）应遵守的约定。
- `demos/`：具体实验的实现、使用说明和实验记录。
- 基础设施的架构和使用文档由其所属仓库维护。

## 表述

- **减少不必要的负面表述**。优先直接描述目标、机制、事实和结果；仅在操作禁令、真实限制或证据边界需要时使用否定句。
- 避免反复解释项目「不是什么」，也避免无助于理解当前内容的来源和演变叙述。
- 研究方向、概念定义、实验计划与评价标准以已确认的信息为准。存在实质歧义时先询问，不自行补充或将建议写成既定安排。
- 保持研究假设、已实现机制和实验结果之间的区分。

## 文档与历史

- 正式文档描述当前有效的状态；代码变更和重构历史由 Git 记录。
- 保留具有长期比较价值的实验条件、结果和指标，注明对应代码版本、配置及测试条件。
- 临时内容可放入 Draft，按 [Draft 隔离规则](drafts.md) 管理。
