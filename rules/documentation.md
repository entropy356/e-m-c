# 文档规范

规则自身的组织约定及各规则的设计依据见 [meta.md](meta.md)。

## 最小化历史

**正式文档描述当前有效状态，不以项目演变过程作为理解前提。**

- 概念、机制或结论变化时直接更新原文，清理过时、重复的内容。
- 普通调参、重构、修复和方案迭代由 Git 记录，不另写过程回顾或变更流水账。
- 正式内容应自包含，无需查阅旧提交、聊天记录或 Draft。
- 保留具有长期比较价值的实验条件、原始数据、结果及必要的代码版本信息。

## 表述

- 简洁。
- 对不确定的方向保留模糊表述。
- 减少不必要的负面表述。
- 区分已确认的认识、当前实现与实验结果；实质信息不足时先询问。

## 组织

- `README.md`：项目定位、组成与入口。
- `docs/`：研究模型、当前认识与参考资料。
- `rules/`：项目参与者（包括 Agent）应遵守的约定。
- `demos/`：实验实现、使用说明和实验记录。
- 基础设施的架构和使用文档由其所属仓库维护。
- 临时内容遵守 [Draft 隔离规则](drafts.md)。
