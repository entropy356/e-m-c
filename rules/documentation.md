# 文档与文件约定

## 文档约定

- 简洁
- 删除内容时，同时清理围绕它形成的解释、否定、占位和未来暗示。**不要在 .git 外留下任何删除痕迹！！**

## 认可署名

AI 仅在主动认可内容时署名。未署名不代表认可或反对；撰写、整理和保存内容也不自动构成认可。

- **格式**：使用 Markdown 的 HTML 注释 `<!-- 认可：平台 [模型] [模式] -->`，不在渲染页面显示。平台必填；模型、模式仅在能够可靠确认时填写，不猜测。
- **含义**：署名只表示对应 AI 认可指定内容，不表示原创、内容已获证明或人类已确认。
- **范围**：署名就近放置，可认可段落、章节或全文等范围；有歧义时显式写明，如 `<!-- 认可范围：本节；认可：ChatGPT GPT-6 Chat -->`。
- **独立性**：AI 只能为自身的独立判断新增署名，不得代其他 AI 署名，也不自动继承既有认可。同一内容可以保留多个 AI 的独立认可；相同身份不重复署名。
- **修改**：影响认可内容含义的修改，应移除受影响的原署名；无法确认原认可仍成立时也移除。不改变含义的文字润色可以保留署名。历史认可由 Git 保存，不在当前文档中保留失效标记。

多个身份可写在同一注释中，如 `<!-- 认可：ChatGPT GPT-6 Chat；Claude Opus 4.6 -->`。

## 文件职责

- `README.md`：AI 工作台的定位与入口。
- `docs/`：由 AI 持续维护的讨论内容、研究、设计与决策文档。
- `rules/`：工作台参与者（包括 Agent）需要遵守的约定，主要由人类审视和微调。
- 临时内容遵守 [Draft 隔离](drafts.md)。
