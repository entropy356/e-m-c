# 文档与文件约定

## 文档约定

- 简洁
- 减少不必要的负面表述
- 删除内容时，同时清理围绕它形成的解释、否定、占位和未来暗示。**不要在 .git 外留下任何删除痕迹！！**

## 认可署名

AI 仅在主动认可内容时署名。未署名不代表认可或反对；撰写、整理和保存内容也不自动构成认可。

- **格式**：使用 Markdown HTML 注释 `<!-- 认可：平台 [模型] [模式] -->`。平台必填，模型和模式仅在能够可靠确认时填写，不猜测。多个 AI 可使用 `；` 分隔身份。
- **含义**：署名表示该 AI 独立认可指定内容，不表示原创、已获证明或人类已确认；不得代其他 AI 署名，也不得继承其他 AI 的认可。同一范围内相同身份不重复署名。
- **范围**：默认认可注释之前的上一非空文本块（以空行分隔）；也可指定 `<!-- 认可范围：本节；认可：ChatGPT GPT-6 -->` 或将 `本节` 换成 `全文`。本节指最近的 Markdown 标题至下一同级或更高级标题前。
- **版本与失效**：GitHub Actions 自动将新增认可绑定到具体 Git 提交和内容指纹，归档为 `endorsements/v1/` 下的附注 Tag。认可范围内任何文字变化均使原署名失效，包括润色与标点；自动移除失效署名。历史版本由 Git Tag 保存，当前文档不保留失效说明。
- **注意**：自动处理在推送到 `main` 后运行；工作流未成功完成前，不应将尚未验证的署名视为有效。

## 文件职责

- `README.md`：AI 工作台的定位与入口。
- `docs/`：由 AI 持续维护的讨论内容、研究、设计与决策文档。
- `rules/`：工作台参与者（包括 Agent）需要遵守的约定，主要由人类审视和微调。
- `rules/workflows/`：研究、日常整理等工作流程。
- 临时内容遵守 [Draft 隔离](drafts.md)。
