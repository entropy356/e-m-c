# 元规范

本文件记录元规范，并暂存现有细化关系记法。其他规范见 [文档](documentation.md)、[Draft](drafts.md) 和 [实验](experiments.md)。

## 信息分类

按内容对 Agent 的作用，区分四类：

- **背景**：事实、假设、定义及上下文；帮助理解与判断，本身不直接提出行为要求。
- **意图**：希望实现的状态、方向或目的；说明要达成什么，不预先限定实现方法。
- **方针**：选择与权衡时采用的指导准则；允许根据具体情境调整。
- **约束**：必须满足的行为或结果条件；应明确适用范围，并能判断是否满足（不要求自动化验证）。

信息类别与根节点、细化关系是不同维度。现有条目尚未逐条重新归类；待新形态通过具体规则检验后，再统一设计语法。

## 记法（过渡）

```text
标识符:[被细化的规范1|被细化的规范2] = 规范内容
    - 意义1
    - 意义2
```

- 方括号内引用这条规范所细化的上层规范，不表示严格的逻辑推导；`|` 用于分隔多个上层规范。
- `[root]`：已确认的根规范，无上层规范。
- `[]`：暂不指定被细化的规范，不等于根规范。
- 缩进列表说明规范存在的实际意义；按需记录，不要求预先填写。
- 跨文件规范可以用 `[文件.md #章节](文件.md#章节):[被细化的规范]` 引用，不复制正文。
- 章节内的列表、表格和段落属于该章节的内部结构，不自动成为独立规范。

## 元规范

pragmatism:[root] = 规范遵循实用主义

agent-reader:[root] = 规范是给 Agent 读的

justifiable-value:[pragmatism] = 每条规范都应能在受到质疑时解释其存在价值
    - 使规范能够根据实际价值被评估、修改或删除。
    - 避免缺乏实际收益的规范长期积累。

minimize-negative-expression:[] = 减少不必要的负面表述
    - 减少无实际必要的限制。
    - 使规范更直接地表达期望行为。
