# e-m-c

> 情绪化记忆库与时间感知（Emotion · Memory · Clock）

e-m-c 探索 Agent 如何**带着情绪形成、提取和改变记忆，以及如何理解经历与时间的关系**。关注点不是任务正确率最大化或通用 Agent 框架，而是记忆、情绪与时间如何共同塑造持续的内部状态和行为。

## 研究主线

- **情绪化记忆库**：将记忆内容（Content）与感受关联（Affect）区分开，研究当前情绪如何影响记忆的写入、检索与保留，以及被唤起的记忆如何反过来影响情绪。
- **时间感知**：探索 Agent 如何区分事件的先后、间隔与持续时间，如何将时间信息关联到记忆，以及情绪、记忆如何影响它对时间的判断。这是研究方向，**不等于已经实现了主观时间感**。
- **相互作用**：研究记忆与情绪随时间演化的闭环，而非把情绪当作回复标签、把 Clock 当作一个定时器就算完成研究。

研究中的概念与待验证问题见 [概念模型](docs/model.md)。

## 当前进展

**[Demo 1 — 情绪化记忆库的 Emotion–Memory 反馈](demos/demo1-emotion-memory/README.md)** 已探索情绪状态与记忆读写的双向作用，并保留了对照数据。它没有验证时间感知：现有固定间隔的运行功能只是调度，不是 Agent 对时间的理解。

~~~bash
cd demos/demo1-emotion-memory
python -m emc serve
~~~

需要 Python 3.10+；离线模式无需第三方依赖。实现、运行方式与证据边界见 Demo 文档。

## 实验与基础设施

项目同时包含**实验**和与实验相互促进的**基础设施**。

实验负责探索情绪化记忆与时间感知的机制，发现并验证需求；基础设施负责运行、模块组合、状态持久化、时间/事件输入及可观测性等通用能力，不预先规定唯一的记忆算法、时间模型或认知流程。

[**e-m-c.runtime**](https://github.com/entropy356/e-m-c.runtime) 来自此前的长期记忆实验，正在以**模块化重构为基础设施**作为目标。目前它仍是围绕无 Emotion 长期记忆聊天流程组织的原型，尚未集成进本仓库；不能将其现状等同于项目最终的情绪化记忆库与时间感知机制。
