# Demo 与实验约定

Demo 是围绕一个稳定研究问题持续演化的实验单元。

- **问题不变**：直接修改原 Demo。算法、参数、模型、实现和重构由 Git 记录。
- **问题改变**：新建 Demo，使用稳定编号和简短主题名。编号不因内部实现调整而改变。
- **不过早抽象**：允许不同 Demo 暂时重复实现，只有稳定的共同需求出现后才提取共享模块。

## 验证方式

先做体感测试，再根据发现的问题设计对照实验。体感观察与实验结果应明确区分。

## 文档与实验记录

项目文档描述当前有效的设计和使用方式，不维护实现变迁的叙述；普通代码修改和重构由 Git 记录。

以 [Demo 1](../demos/demo1-emotion-memory/README.md) 为例：

```text
demos/demo1-emotion-memory/
├── README.md       # 当前目标、机制、运行方式、观察和局限
├── emc/            # 实现
├── tests/          # 测试
├── experiments/    # 值得长期比较的实验记录
└── results/        # 原始数据与结构化指标
```

仅将有长期比较价值的实验条件、原始结果和指标单独保留，注明对应代码版本、配置和测试条件。普通调参、Bug 修复和重构无需另写过程记录。

实验记录跟随产生它的 Demo；跨 Demo 的比较和项目级结论放在 `docs/`，稳定结论可纳入 [核心设计](design.md)。
