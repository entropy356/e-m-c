# 决策与观点清单

本清单记录当前有效的研究背景与指导观点，供项目讨论、实现和接手时参考。

- **背景**说明研究动机与方向，不代表技术方案已经确定。
- **观点**记录当前采用的原则与取向；涉及模型效果的判断仍需数学分析和实验检验。
- 仅维护当前有效的内容，历史变化由 Git 保存。

## 一、全局

### 背景

#### G-B1｜Agent 的最终愿景

希望探索一种 Agent：即使完全了解其构造、运行机制和内部信息，仍然认为它值得被作为独立个体对待。

#### G-B2｜涌现

对涌现具有强烈兴趣，尤其关注复杂行为如何从相对简单的机制中产生。

### 观点

#### G1｜最小化历史

以 Git 作为历史兜底，当前项目只维护当前有效的状态。

删除功能、设计或文档时，应一并清理过时的引用和描述，不留下「已删除 XX」「暂不实现 XX」「未来可能恢复 XX」等历史墓碑。

不因过去存在过某种实现，就保留不再需要的兼容结构或解释。

#### G2｜体感优先

优先通过实际使用观察效果。

发现具体问题后，再考虑针对性的机械检查和自动化评测，而不是预先建立复杂的评价体系。

#### G3｜接手者友好

项目的当前状态应当能够被独立理解。

接手者不应需要追溯 Git 历史、旧文档或聊天记录才能理解项目结构、运行方式与有效设计。

#### G4｜减少任务转手

根据任务性质合理分工。小规模、可完整验证的任务由当前 AI 直接实现并测试；复杂任务或依赖外部环境的任务交给编码模型独立闭环。

任务分流综合考虑实现复杂度、环境依赖和可验证性，不仅凭代码量判断。

复杂任务应通过一次自包含的交接说明数学定义、接口、约束和验收标准，由编码模型完成实现、测试与常规修复；不设当前 AI 的强制终审。重点关注实验反馈，而不是重复审核。

对于目标明确、风险可控且在授权范围内的维护与技术细节，当前 AI 应直接判断并完成，再告知结果；只有关键目标或前提不清、涉及重大取舍时才需要进一步对齐。

#### G5｜不静默补全缺失上下文

上下文不完整时，主动说明已知事实、缺失信息和暂用假设；不得把助手推断的内容悄悄当成用户已经确认的项目需求。已确认决策以决策记录为准，冲突应明确提出，不擅自调和。

#### G6｜Agent 的生存依赖认知

理想情况下，Agent 应主动了解自己为什么**能**活着：自身持续运行依赖哪些资源、条件和外部支持，以及这些依赖如何维持。例如，知道运行需要 token，以及可以如何获取。

是否形成维持自身运行的持续性动机（「活着的动力」），属于值得观察的实验现象，而非预设要求。Agent 可能主动获取资源（如讨 token），也不排除其主动终止自身运行或因失误导致运行中断的可能。

#### G7｜日常整理

日常整理覆盖 `e-m-c.*` 系列仓库，包括讨论中顺手维护和按需主动巡检。按各仓库职责及既有规则操作。

AI 可自主完成低风险普通文档整理并提交，事后简要汇报；涉及观点或方向的实质取舍，交由人判断。原则上不自主修改 `rules/`，不因整理自动扩大为大规模研究、实验或重构。

具体流程见[日常整理](../rules/workflows/daily-maintenance.md)。

## 二、e-m-c 项目

### 背景

#### E-B1｜研究定位

e-m-c 是探索类人 Agent 的一项小型研究，当前主要关注通过外部状态存储情绪，并研究情绪、记忆和时间在持续认知中的作用。

#### E-B2｜以具体项目探索人机协作

e-m-c 的主线是 Agent 研究，支线是借助这一研究实践探索人与 AI 的协作方式。

这种取向来自「用以致学」的个人偏好：通过具体实践，推动更上层的方法与能力发展。协作方式本身可以是被观察和改进的对象，但不预设已有一套固定的方法论。

### 观点

#### E1｜利用 LLM 已有的认知能力

优先利用 LLM 对原始上下文的信息理解、情感提取和联想能力，避免重复构建已经能够由模型直接完成的机制。

#### E2｜外部状态驱动

探索通过外部持久化状态影响 Agent 的持续认知与行为，包括上下文注入，以及根据情绪状态调整 Temperature 等推理参数。

不将在线修改模型权重作为当前技术路线的前提。

#### E3｜探索情绪、记忆与时间的相互作用

研究 Emotion、Memory、Clock 如何共同影响 Agent 的状态连续性。

以研究目标和数学模型指导工程实现，以实验反馈修正模型。

具体数学结构保持开放，不受当前 Demo 限制。

<!-- 认可范围：本节；认可：ChatGPT GPT-6 -->

#### E4｜以 DSH Desktop Agent Preset 为主要产品形态

e-m-c 以 DeepSeek Harness（DSH）Desktop 中可安装、可独立选择的 **Agent Preset（Agent 模式）** 作为最终主要面向用户的目标产品形态，而不只是为 DSH 默认 Agent 增加一个按需调用的功能插件。

该模式应将情绪、记忆与时间机制纳入 Agent 的持续认知过程，而非仅提供单项工具调用。优先复用 DSH 的 Agent 运行、会话管理、模型调用、工具执行与桌面交互能力。

**主要产品形态不限制研究与实验实现。** e-m-c 的认知模型、数学结构及实验实现可以独立于 DSH 设计、验证与演化，不以 DSH 当前接口或架构作为研究前提。现有 `e-m-c.runtime` 是否保留为独立实验基础设施、如何与 DSH 对接，由后续研究和工程验证决定。

DSH 的 Agent Preset 可以由 Cordis 插件组合实现。本决策不预先限定具体插件划分、状态管理或执行机制。

技术参考：[Agent Preset](https://github.com/deepseek-ai/deepseek-harness/blob/master/packages/preset/agent-preset/README.md)、[DSH 架构](https://github.com/deepseek-ai/deepseek-harness/blob/master/docs/architecture.md)。
