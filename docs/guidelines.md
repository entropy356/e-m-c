# 项目规范

## 总体原则

- 不以 Agent 的任务执行能力为设计中心。
- 不让临时实现反过来决定概念与数学结构。

## 局部原则

### Memory

- 记忆不应只保留当前被判断为「有用」的信息。
- 记忆的保留、权重衰减与激活是不同的问题，不应混成一个判断。

### 向量表示

- **Content 与 Affect 是概念上独立的向量空间**：前者表示内容，后者表示感受。
- 即使实验中暂时共用 embedding 模型，代码结构也不应默认语义相似性等于感受相似性。

## 文档与历史

- 文档描述当前有效的设计和使用方式，不维护实现变迁的叙述；普通代码修改和重构由 Git 记录。
- 只有具有长期比较价值的实验条件、原始结果和指标才单独保留，并关联代码版本、配置和测试条件。
- 实验记录跟随产生它的 Demo；跨 Demo 的比较和项目级结论进入 `docs/`。
- **严格隔离 Draft**：以 `.draft` 结尾的文件、目录、Git 分支和仓库均为临时对象。任何 Draft 边界外的持久内容（包括其他 Draft）均不得引用或依赖它；不确定时默认禁止。具体约束见 [Draft 严格隔离](drafts.md)。

## 验证策略

先做体感测试，再根据发现的问题设计对照实验。体感与实验数据的结论应明确区分。
