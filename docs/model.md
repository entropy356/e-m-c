# 情绪化记忆库与时间感知：概念模型

e-m-c 的研究对象是**情绪化记忆库**与**时间感知**，以及两者在持续运行的 Agent 中的相互作用。Emotion、Memory、Clock 是探索这些问题的概念入口，不是三个已经完备的模块。

本文区分研究假设、概念结构与现有实现；不能把某个 Demo 的公式或 Runtime 的固定执行流程当作完整模型。已实现的算法、参数和观察见 [Demo 1](../demos/demo1-emotion-memory/README.md)。

## 情绪化记忆库

记忆不只是供检索的文本，也可能携带形成和重访它时的感受关联。这里区分两个概念上的向量空间：

- **Content**：记忆所表达的内容。
- **Affect**：记忆关联的感受；语义相近不意味着感受相近。

二者在模型层面独立。Demo 1 暂时借同一个 embedding 模型分别编码内容和感受，这是实验近似，不是两种空间在概念上等同。

需要分开研究记忆的**保留、可提取性、激活、衰减和替代**。被检索到、被模型引用、值得长期保留并非同一判断；尤其不能把记忆价值直接化约为当前任务效用或使用次数。

### Emotion 与 Memory 的反馈

Emotion 被视为连续演化的内部状态，而非贴在回复上的情绪标签。其惯性与更新可用一种抽象表达示意：

\[
E_{k+1}=\rho E_k+\Delta E_k
\]

这不是对所有实验的统一更新公式。当前情绪可能影响哪些记忆容易被唤起、怎样写入感受关联；被唤起的记忆又可能通过认知改变后续情绪。如何形成稳定而不失真的循环，仍需实验检验。

## 时间感知

这里的“时间感知”不等同于按固定间隔执行一次循环。至少需要区分：

- **外部时间**：事件发生的时刻、先后、间隔和持续时间。
- **内部推进**：模型认知轮次、状态更新次数及调度节奏；一轮不天然代表固定的现实时间。
- **记忆中的时间**：记忆如何保存事件的时间线索、顺序与相互间隔，以及这些信息如何参与回忆和变化。
- **对时间的判断或体验**：Agent 能否根据经历与当前状态判断经过了多久、什么事情更近或更久；情绪是否改变这种判断，仍属于待研究问题。

当前尚未给出经过验证的时间感知数学模型。不能因为系统保存了时间戳、能按时触发或按轮次衰减，就宣称它具有时间感知。

## 记忆、情绪与时间如何联系

研究重点在于三者的联系，而不仅是并列增加功能：

- 同一段经历，是否会因当前情绪不同而以不同方式被回忆？
- 记忆的远近、间隔与反复出现，如何影响其可提取性与情绪关联？
- 情绪是否影响 Agent 对持续时间或时间距离的判断？如何将这种变化与模型输出随机性区分？

这些是**研究问题，不是已经得到证实的规律**。

## 认知过程与基础设施

LLM 的认知过程、某轮实际提供给模型的上下文、跨轮保留的内部状态，应明确区分。一次检索只会把记忆库的部分内容交给模型，模型上下文不是完整的记忆库。

基础设施 Runtime 负责组织运行、提供时间与事件输入、管理持久状态和可观测性；**情绪化记忆与时间感知的具体机制不应被写死在基础设施里**。

Clock 可以提供推进节奏和触发来源，但调度能力本身不构成时间感知。实验需要能够独立替换、对照与观察这些机制。

## 当前验证边界

[Demo 1](../demos/demo1-emotion-memory/README.md) 研究 Emotion 与 Memory 对记忆读写的影响：实现了状态更新、情绪关联的检索评分、写入与按需检索。它只有固定间隔自动运行与轮次信息，没有证明时间信息如何进入记忆，也没有验证 Agent 对时间的判断。

[e-m-c.runtime](https://github.com/entropy356/e-m-c.runtime) 是从长期记忆实验抽离、准备模块化重构的基础设施原型，不是时间感知模型的既有实现。
