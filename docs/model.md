# 情绪化记忆库与时间感知：概念模型

本项目探索情绪化记忆库与时间感知。以下记录当前已明确的概念，以及 Emotion、Memory、Clock 的关系。具体实验实现与观察见 [Demo 1](../demos/demo1-emotion-memory/README.md)。

## 情绪化记忆库

记忆包含内容及其感受关联。模型区分两个概念上独立的向量空间：

- **Content**：记忆的内容表示。
- **Affect**：记忆的感受关联。

语义相似性与感受相似性是不同的关系。Demo 1 暂时用同一个 embedding 模型分别编码 Content 和 Affect。

Memory 可分别讨论记忆的**保留、可提取性、激活、衰减和替代**。记忆价值不只取决于当前任务效用；可检索性、实际引用和长期保留也属于不同的问题。

### Emotion 与 Memory 的反馈

Emotion 是连续变化的内部状态，具有惯性，并可受输入与认知过程影响。一种抽象表达为：

\[
E_{k+1}=\rho E_k+\Delta E_k
\]

当前 Emotion 参与记忆的检索与写入；被提取的记忆参与认知，认知形成的感受又影响后续 Emotion。具体计算方式与测试结果见 Demo 1。

## 时间感知

时间感知是项目的研究方向之一。其具体概念、数学结构和实验问题仍待明确。

Clock 当前主要用于描述运行的推进与触发。Demo 1 实现了按固定间隔运行的方式，并记录认知轮次。

## 认知与基础设施

- **持续状态**：跨轮保存的 Emotion、Memory 等信息。
- **模型上下文**：当前一轮向 LLM 提供的输入及选取的信息。
- **认知过程**：LLM 基于可见上下文进行理解、生成，并参与状态更新。

Runtime 提供生命周期、模块组合、持久化与可观测性等共用能力，为实验中不同的情绪化记忆和时间机制提供运行环境。

[e-m-c.runtime](https://github.com/entropy356/e-m-c.runtime) 是准备模块化重构为基础设施的 Runtime 原型。
