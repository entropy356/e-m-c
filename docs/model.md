# E-M-C 概念模型

e-m-c 研究具有持续内部状态、能够按自身节奏运行的 Agent。目标是探索更接近人的行为，而不是优化任务正确率或实用性：它可以记错、受旧结论影响，也可以因为当前状态不同而对同一输入产生不同反应。

本文描述研究对象、概念区分和当前假设，而非某个实现的强制接口。具体算法、参数、已实现能力和实测结果见 [Demo 1](../demos/demo1-emotion-memory/README.md)。概念上的可能性不等于现有 Demo 已实现。

## 状态与认知的边界

- **持续状态**：Emotion、Memory，以及控制运行节奏的 Clock。
- **认知过程**：LLM 基于当前输入和可见状态进行理解、联想、生成与决策，并提出状态变化。
- **模型上下文**：某轮实际提供给 LLM 的有限信息，不等同于完整记忆，也不等同于持续状态。

**Content 与 Affect 是概念上独立的向量空间**：前者表示内容，后者表示感受；语义上的接近不意味着感受上的接近。Demo 1 暂时复用一个 embedding 模型分别生成两种表示，不能将这种实现近似当成概念上的等同。

## Emotion

Emotion 是连续变化的高维状态，不预设固定情绪标签或中性基准。它具有惯性，并受输入、认知及行动结果影响，可用抽象形式表示为：

\[
E_{k+1}=\rho E_k+\Delta E_k
\]

Emotion 可以调节记忆的读取与写入，也可以作为未来影响 Clock 的因素。它不是直接塞给 LLM 的一个情绪标签。

## Memory

Memory 由多条记忆组成。每条记忆可分别携带内容表示、感受关联及其他状态；保留、可提取性、衰减、激活和替代不必由同一个指标决定。

记忆的保留不应仅由当前的任务效用决定。**可被检索到**、**被实际引用**与**值得保留**是不同概念，不能直接用使用次数或任务效用代替记忆的价值。

当前状态影响哪些记忆容易被取出。检索进入上下文的通常只是记忆库的子集。Agent 可以在认知过程中尝试主动索取更多记忆，但检索结果仍受其状态、查询与访问机制限制。

## Clock

Clock 表示 Runtime 的运行节奏，使一次运行不一定由用户输入触发。它负责决定何时推进，不直接规定 Memory 的算法。

Emotion 对 Clock 的影响属于设计方向；Demo 1 只提供固定间隔的运行循环，尚无情绪驱动的频率调整。

## 运行过程

```text
当前持续状态 + 外部输入或内部触发
                    ↓
                 记忆检索
                    ↓
                 LLM 认知
                    ↓
                 状态更新
              ┌─────┼─────┐
              ↓     ↓     ↓
            Emotion Memory 其他状态
                    ↓
               后续运行与检索
```

这里的「轮次」不等于现实时间。状态变化的来源应尽可能可观察，以便区分机制作用、模型输出差异和实现错误。

这是一种概念性的运行示意，而不是对所有实验、认知策略或未来基础设施流程的强制规定。
